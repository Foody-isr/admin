## Réalisation et limites

Inventaire mobile en cartes, filtres repliables, tableau desktop/colonnes/tri/pagination/sélection conservés, détails en drawer, symbole C2 réel. Renommage séparé : brouillon stable pendant polling, limite120 runes, alias vide autorisé, garde de sortie/unload et verrou synchrone. Permissions cumulatives par capacités et FoodyPOS alignées sur le backend, garde de route/navigation corrigés pour les rôles matériels. Chargement validé, erreurs distinctes du vide, locale sans GET supplémentaire.

ACK validés ; résultat incertain renommer → GET inventaire et comparaison, nom divergent affiché sans écraser le brouillon. Suppression groupée allSettled conserve les succès, relit les seuls résultats incertains et garde les causes protégées. Annulation de file distingue action confirmée et échec de rafraîchissement ; réponse perdue ne prétend pas confirmer l’annulation. Test d’impression annoncé seulement en file ; réponse perdue requiert vérification explicite du matériel avant nouvelle demande, aucun POST automatique. Focus placé sur retour d’action dans la couche visible.

Limites : absence de version/ETag backend et de garde SPA globale ; le frontend ne peut pas prouver une sortie papier. Contrats réels lus, toutes requêtes de preuve interceptées. Le premier ciblage18/20 est conservé ; correction des permissions et deux scénarios ajoutés, puis22/22 dev et22/22 compilés. Voir progress/verification pour validation complète et horodatage.
